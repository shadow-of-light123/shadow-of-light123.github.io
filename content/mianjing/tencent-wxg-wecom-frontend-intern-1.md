## 面试问题

### 1. 浏览器从输入地址到页面展示的完整过程

**回答**，按时间线串起来：

1. **URL 解析**：浏览器判断输入是否为合法 URL，不是则交给默认搜索引擎处理
2. **缓存检查**：先查强缓存，命中则不发请求，直接使用本地缓存（from disk/memory cache）
3. **DNS 解析**：逐层查询域名对应 IP（浏览器缓存 → 操作系统缓存 → 本地 DNS → 根/顶级/权威域名服务器）
4. **建立连接**：TCP 三次握手；HTTPS 还要再完成 TLS 握手协商加密
5. **发送请求**：构建 HTTP 请求报文，服务端处理后返回 HTML/CSS/JS 等资源
6. **解析渲染**：
   - 解析 HTML 生成 **DOM 树**，解析 CSS 生成 **CSSOM**
   - 遇到同步 JS 会阻塞 DOM 解析（先下载执行完再继续）；`async`/`defer` 的脚本不阻塞
   - DOM + CSSOM 合成**渲染树**，经过 **layout（回流）计算几何信息 → paint（重绘）绘制像素 → composite 合成图层**，最终展示给用户

### 2. 强缓存和协商缓存的区别

**回答**：

| 维度       | 强缓存                                                                                            | 协商缓存                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 核心字段   | `Cache-Control`（HTTP/1.1，`max-age` 相对秒数）/ `Expires`（HTTP/1.0，绝对时间）                  | `ETag` / `If-None-Match`、`Last-Modified` / `If-Modified-Since`                 |
| 是否发请求 | 命中时**不发请求**，状态 200（from cache）                                                        | **要发请求**，命中返回 **304**，复用本地缓存                                    |
| 缺点       | `Expires` 依赖客户端时钟，存在时区/改时间导致失效不准的问题（`Cache-Control` 优先级更高，已替代） | `Last-Modified` 只能精确到秒，1 秒内多次修改无法感知，故引入 `ETag`（内容指纹） |

**完整流程**：请求资源 → 先判断强缓存是否过期 → 未过期直接用本地缓存；过期则发请求携带 `If-None-Match` / `If-Modified-Since` 走协商缓存 → 服务端判断资源没变返回 304，变了返回 200 + 新资源和新缓存字段。

### 3. XSS 攻击的原理、类型与防御

**回答**：

**是什么**：跨站脚本攻击，本质是**恶意代码被浏览器当作页面自己的代码执行了**。重点不在恶意代码怎么来，而在于什么写法会导致它被执行。

**三种类型**：

- **存储型**：恶意代码存进后端数据库（如评论区），前端取出渲染时执行，危害最大
- **反射型**：恶意代码藏在 URL 参数里，用户点击链接后服务端把它拼进 HTML 返回执行
- **DOM 型**：完全由前端 JS 操作 DOM 引入，不经过服务端

**会导致执行的写法**（面试官追问的「具体 API」）：

- 原生：`innerHTML` / `outerHTML`、`document.write`、`eval`、`new Function`、`setTimeout('字符串')`
- 框架里关闭默认转义的口子：Vue 的 `v-html`、React 的 `dangerouslySetInnerHTML`——现代框架对插值默认转义，但这两个 API 相当于**主动放弃转义**

**防御手段**：

- 对用户输入/输出做充分转义（框架插值默认已做）
- 不用 `v-html` / `innerHTML` 渲染不可信内容，必要时先用 **DOMPurify** 消毒
- 配置 **CSP**（Content-Security-Policy）限制脚本来源
- Cookie 设置 `HttpOnly` 防止脚本读取，降低窃取风险

### 4. CSRF 攻击的原理与防御

**回答**：

**核心原理**：利用浏览器「**向哪个域名发请求，就自动携带该域名的 Cookie**」这一特性。攻击者**根本不需要读取到 Cookie 本体**（JS 也读不到跨域 Cookie），而是借浏览器之手直接发请求。

**攻击流程举例**：用户已登录银行 → 点开一个恶意网站 → 恶意网站向银行的转账接口发请求（表单提交 / img / fetch）→ 浏览器判定目标是银行域名，**自动带上银行的 Cookie** → 服务端验 Cookie 通过，误认为是用户本人操作。

**防御**：

- **SameSite**：设置 Cookie 的 `SameSite=Lax/Strict`，限制跨站请求不携带 Cookie
- **CSRF Token**：服务端下发随机 token，写操作必须携带并在服务端校验，恶意网站拿不到 token
- **校验 Origin / Referer**：检查请求来源是否为可信域名
- 关键操作（支付、改密码）加二次验证

**与 XSS 的区别**：XSS 是「在你的页面里执行我的代码」，CSRF 是「借你的身份发我的请求」。

### 5. Webpack 和 Vite 的区别，Vite 为什么开发时快

**回答**：

**为什么快**：

1. **按需加载替代全量打包**：Webpack 启动 dev server 前要把所有模块打包成 bundle，项目越大启动越慢；Vite **不打包业务代码**，利用**浏览器原生支持 ES Module** 这一条件，页面用到哪个模块就按需请求哪个模块
2. **esbuild 预构建依赖**：Vite 底层用 Go 编写的 esbuild 处理依赖预构建，比 JS 实现的 Webpack 快 10~100 倍
3. **HMR 精确到模块**：修改代码只需让受影响的模块失效，不整链路重新构建

**为什么生产环境不用这套方案**：

- 生产需要 **tree shaking、代码压缩、代码分割**等优化，必须真正打包
- dev 的按需加载意味着**每个模块一次网络请求**，模块多时网络开销大；打包后直接加载编译好的产物没有这个问题 → 生产环境 Vite 用 Rollup 打包

### 6. 事件循环：宏任务、微任务的执行顺序

**回答**：JS 是单线程的，靠事件循环支持异步任务。典型例题：

```js
console.log('script start')

setTimeout(() => {
  console.log('setTimeout')
}, 0)

Promise.resolve()
  .then(() => console.log('promise1'))
  .then(() => console.log('promise2'))

console.log('script end')

// 输出：script start → script end → promise1 → promise2 → setTimeout
```

**执行规则**：

1. 先执行同步代码（整段脚本相当于一个宏任务）
2. 遇到异步 API 分类入队：`setTimeout`/`setInterval`/I/O 入**宏任务**队列，`Promise.then`/`queueMicrotask` 入**微任务**队列
3. 每个宏任务执行完后，**清空整个微任务队列**（微任务中产生的新微任务也在这轮清空）
4. 微任务清空后，如有必要渲染页面，再取下一个宏任务，进入下一轮循环

**关键点**：微任务优先级高于宏任务；Promise 构造函数里的代码是同步的，`.then` 回调才是微任务。

### 7. Vue2 和 Vue3 响应式原理的区别

**回答**：

| 维度          | Vue2                                            | Vue3                                       |
| ------------- | ----------------------------------------------- | ------------------------------------------ |
| API           | `Object.defineProperty`                         | `Proxy`                                    |
| 新增/删除属性 | 无法侦测，需 `Vue.set` / `Vue.delete`           | 原生支持（`set`、`deleteProperty` 拦截器） |
| 数组          | 下标和 length 修改无法侦测，靠重写 7 个数组方法 | 直接拦截，下标赋值、length 修改均可侦测    |
| 初始化时机    | 初始化时递归遍历所有属性定义 getter/setter      | 惰性代理，访问到才转化，性能更好           |

**Vue3 响应式核心流程**：

- `reactive(obj)` 返回 Proxy，拦截 get/set 等操作
- **依赖收集（track）**：组件渲染函数执行时访问响应式数据，触发 get 拦截，把当前 effect 存入 `targetMap`（`WeakMap<target, Map<key, Set<effect>>>`）
- **触发更新（trigger）**：数据修改触发 set 拦截，从 `targetMap` 取出该 key 的所有 effect 重新执行，组件随之重渲染
- 基本类型用 `ref`（RefImpl 的 getter/setter 实现 track/trigger），因为 Proxy 只能代理对象

### 8. 从数据变化到视图更新的完整链路

**回答**（面试官追问链：框架怎么感知数据变 → 感知到之后怎么决策改哪个 DOM）：

1. 数据被 Proxy 代理，修改触发 **set 拦截 → trigger**，取出该数据关联的 effect（组件渲染函数）
2. 渲染函数重新执行，生成一棵新的**虚拟 DOM 树**（用 JS 对象描述真实 DOM 结构）
3. **diff 算法对比新旧两棵虚拟 DOM 树**，找出最小变更
4. **patch** 阶段把差异应用到真实 DOM 上，完成视图更新

**关键点**：diff 的输入是**前后两棵虚拟 DOM 树**，不是真实 DOM——直接操作真实 DOM 对比代价太高，虚拟 DOM 让「算差异」在纯 JS 层完成，最后只做最少量的真实 DOM 操作。

### 9. diff 算法有哪些优化策略

**回答**（目标是尽可能少地对比、尽可能少地操作 DOM）：

- **只同层级比较**：不跨层级 diff，同级节点 tag/key 不同直接整棵子树替换，不再深入对比
- **sameVnode 判断**：tag + key 相同才认为是同一节点可复用
- **头尾指针优化（针对列表）**：Vue2 双端比较（旧头新头、旧尾新尾、旧头新尾、旧尾新头四个方向），优先处理首尾相同的常见场景，减少中间乱序部分
- **最长递增子序列**：Vue3 对中间乱序部分求最长递增子序列，得到不需要移动的节点集合，最小化 DOM 移动（insertBefore）操作
- **编译时优化**：Vue3 的静态提升（静态节点只创建一次）、patchFlag 靶向更新（跳过肯定没变的属性）

### 10. key 的作用，给 key 和不给 key 的区别

**回答**：

- **key 是 vnode 的唯一标识**，sameVnode 复用判断依赖 `tag + key`
- **不给 key**（等于用索引当 key）：列表插入/删除时节点按位置错误复用，导致不必要的更新甚至**状态错位 bug**（如输入框内容串位），性能也差
- **给稳定唯一的 key**：diff 能精确知道哪个节点变了、哪个只是移动了位置，只更新真正变化的节点、复用其余节点

### 11. 大数组逐项跑算法导致页面卡死，怎么解决

**回答**：长任务持续占用主线程，页面无法响应交互也无法渲染。三种思路：

1. **时间分片（宏任务调度）**：把大数组 `slice` 成小块，每块处理完用 `setTimeout(runNext, 0)` 调度下一块——**宏任务之间浏览器有机会渲染和响应事件**
   - **易错点**：用 `Promise.then` / `queueMicrotask` 分片**无效**——微任务队列会在本轮连续清空，10 个分片和一个大循环执行起来没有区别，仍然连着阻塞
2. **Web Worker**：纯计算任务搬到 worker 线程执行，主线程零阻塞，通过 `postMessage` 传结果，适合 CPU 密集型场景（最优解）
3. **requestIdleCallback**：利用浏览器空闲时间分批执行，不抢占高优先级任务

**核心理解**：卡顿的根源是「长任务独占主线程」，解法本质都是把长任务打散——要么让出主线程（宏任务分片），要么干脆离开主线程（Worker）。

### 12. SSE 和 WebSocket 的区别及项目选型

**回答**：

| 维度     | SSE                                               | WebSocket                 |
| -------- | ------------------------------------------------- | ------------------------- |
| 协议     | 基于普通 HTTP（`text/event-stream`）              | 独立协议（HTTP 101 升级） |
| 通信方向 | 单向（服务端 → 客户端）                           | 全双工双向                |
| 数据格式 | 仅文本（UTF-8）                                   | 文本 + 二进制             |
| 重连     | `EventSource` 自动重连，支持 `Last-Event-ID` 续传 | 需自己实现心跳 + 重连     |

**项目选型**：

- **AI 对话流式输出选 SSE**：只需服务端把 LLM 逐 token 生成的文本推给客户端，纯单向场景，SSE 轻量且自带重连
- **语音实时转写选 WebSocket**：客户端要持续上传麦克风音频流，同时接收服务端返回的转写文本，双向实时通信且音频是二进制数据，SSE 做不到客户端向服务端推流

## 手撕代码

### 1. 带优先级的合法括号序列

要求：给定一个只包含 `(`、`)`、`[`、`]`、`{`、`}` 的字符串，判断是否合法：

1. 括号必须两两匹配，不能出现单边括号
2. 嵌套时按 `{} > [] > ()` 的优先级，**外层优先级必须 ≥ 内层**（低优先级不能嵌套高优先级）。例：`{[()]}`✅、`({[]})`❌、`([])`❌

```js
/**
 * 判断括号字符串是否有效
 * 原题：必须成对匹配且顺序正确
 * 附加要求：嵌套时按 {} > [] > () 的优先级，外层优先级 ≥ 内层
 * @param {string} s
 * @return {boolean}
 */
const isValid = function (s) {
  const stack = [] // 栈：存期待出现的右括号
  // 优先级：} 最高（3），] 中等（2），) 最低（1）
  const priority = { ')': 1, ']': 2, '}': 3 }

  for (let i of s) {
    if (i === '(') {
      // ) 优先级最低，嵌套在任何括号内都不会违反「外层 ≥ 内层」，直接入栈
      stack.push(')')
    } else if (i === '[') {
      // ] 优先级为 2，若外层期待的是 )（优先级 1），说明低套了高，非法
      if (stack.length > 0 && priority[']'] > priority[stack.at(-1)])
        return false
      stack.push(']')
    } else if (i === '{') {
      // } 优先级最高，外层必须是 } 才能包住它
      if (stack.length > 0 && priority['}'] > priority[stack.at(-1)])
        return false
      stack.push('}')
    } else {
      // 遇到右括号，检查是否与栈顶匹配
      if (i !== stack.pop()) return false
    }
  }

  // 所有左括号都匹配完才有效
  return stack.length === 0
}

// 测试
console.log(isValid('{[()]}')) // true：优先级由外到内递减
console.log(isValid('({[]})')) // false：{ 嵌套在了低优先级的 () 里
console.log(isValid('([])')) // false：[] 嵌套在了低优先级的 () 里
console.log(isValid('([]')) // false：单边括号
console.log(isValid(')(')) // false：顺序错误
```

**关键点**：

- 基础合法性用**栈**：遇到左括号压入「期待的右括号」，遇到右括号弹栈比对
- 优先级约束在**左括号入栈时检查**：当前括号的优先级不能高于栈顶（即外层）括号，等价于「外层优先级 ≥ 内层」
- `(` 分支无需检查：`)` 优先级最低（1），嵌套在任何括号里都不违反规则
- 一次遍历 O(n)，空间 O(n)
